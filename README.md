# Transaction Reconciliation Assistant

An auditable RAG workflow that compares source and settlement ledgers, classifies breaks in SQL, retrieves controls from the FFIEC BSA/AML Examination Manual, and uses a local FLAN-T5 model to explain the result. PostgreSQL stores both operational records and document passages; pgvector and PostgreSQL full-text search provide hybrid retrieval.

## Business problem

Operations teams need to explain why two transaction ledgers disagree and identify the policy section relevant to follow-up. This project separates deterministic reconciliation from regulatory retrieval: SQL decides whether a record matches; the assistant returns evidence from the manual with page and passage identifiers. Retrieved text never changes the financial result.

## Data

The regulatory source is the official 2010 consolidated **FFIEC BSA/AML Examination Manual**, preserved in the [FDIC archive](https://archive.fdic.gov/view/fdic/4074/fdic_4074_DS3.pdf). It contains 439 PDF pages and its SHA-256 is recorded in the pipeline output. The ledgers are deterministic synthetic financial records because public transaction data cannot represent private settlement ledgers or known reconciliation truth. The generator creates 25,000 records and injects exactly 275 controlled breaks for repeatable testing.

Raw PDFs and generated Parquet files are excluded from Git. The download script retrieves the real manual; the pipeline recreates the ledgers.

## Architecture

```text
Official FFIEC PDF -> page-aware chunking -> MiniLM embeddings -> PostgreSQL + pgvector
                                                                    |
Generated source ledger -----> SQL full-outer reconciliation <------+
Generated settlement ledger -> classified exception report          |
User question -> domain expansion -> vector + full-text RRF search -> FLAN-T5 -> cited answer
```

## Run locally

Requirements: Python 3.11+, Docker, and Docker Compose.

```bash
python3 -m venv .venv
source .venv/bin/activate
make install
cp .env.example .env
make download
docker compose up -d
make pipeline
make test
```

No paid API or API key is required. The first pipeline run downloads the open-source embedding and generation models. Configuration lives in [`config/pipeline.yml`](config/pipeline.yml).

## Guardrails

The prompt restricts generation to retrieved passages, citations are attached from retrieval metadata rather than generated by the model, and a score gate rejects weak evidence. This is a portfolio implementation, not legal or compliance advice. The archived 2010 manual is used for a stable, reproducible benchmark; current examination guidance should be checked at the [FFIEC manual site](https://bsaaml.ffiec.gov/manual).
